## v1.18.7

Reviewer runtime reliability for **GitHub Pulls Show Reviewers**.

### Navigation

- Show reviewers when a tab first loaded at GitHub's home, notifications,
  `/pulls`, `/issues` or a profile page navigates to a repository pull request
  list. The content script now loads on every `github.com` page and stays inert
  outside pull request list routes.
- Load reviewers on a pull request list reached by in-page navigation from
  another repository or from a non-repository page, instead of staying empty
  until reload.
- Stop requesting reviewers for the list being left during navigation, and
  handle one navigation once however many page events report it.
- Retry repository discovery on the same page after a transient background
  failure.

### Reviewer accuracy

- Follow GitHub's pagination links in the `/repositories/{id}/...` form, so
  review states are correct on pull requests with more than 100 reviews and the
  page-level metadata batch covers older visible pull requests.
- Read the newest issue events on pull requests with more than 200 events, so
  a re-requested reviewer shows as a confirmed re-request instead of unverified.
- Keep rendering the rest of the page when GitHub returns one unexpected pull
  request record, and accept pull requests whose author account is `null`.

### Access banner

- Show the access banner above the list on GitHub's Preview layout instead of
  below the page, and follow GitHub's theme colors. Classic placement is
  unchanged.

### Background activity

- Stop idle GitHub tabs from restarting the service worker about every thirty
  seconds. Account, preference and language changes still reach a visible pull
  request list without a reload.
- After the primary rate limit is exhausted mid-page, hold the remaining rows'
  requests until the reset time. Disconnect the page observer outside pull
  request lists, and request avatars at 48px.

### Tests and tooling

- Teach the live GitHub canary the repository-id pagination pages and the
  newest-page re-request rule, and close the install-time options page reliably
  before each packaged E2E test.
- Update Prettier to 3.9.9 and ESLint to 10, and defer TypeScript major updates
  until `typescript-eslint` supports them.
- Remove an unused failure channel from the reviewer page controller and
  extract its per-pull request bookkeeping.

### Compatibility

- Permissions, GitHub App scope, authentication, stored data and all five
  interface languages are unchanged. The content script match pattern widens
  from `https://github.com/*/*` to `https://github.com/*`, which the existing
  host permission already covers, so Chrome shows no new permission warning.
  The privacy policy describes where the script loads and where it reads.
- Rows that stay on screen unchanged across a URL change revalidate up to two
  seconds later than before.
- All five store descriptions and all 15 screenshots are unchanged; reuse the
  verified saved-listing baseline.
