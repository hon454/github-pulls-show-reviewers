## v1.15.0

Minor release for **GitHub Pulls Show Reviewers** that reduces avoidable
network bursts and repeated content-script work on active GitHub pull-request
list pages without changing the reviewer information shown.

### Highlights

- Uncached reviewer-summary requests now pass through a four-slot,
  abort-aware FIFO scheduler. Rows render progressively in DOM order instead of
  dispatching every request at once.
- Fresh and stale cache entries still render before the network queue, and
  repeated processing of the same pull request still joins one in-flight
  request.
- Route changes, account changes, and content-script invalidation cancel queued
  work before it sends a background request. Active work is also aborted, and a
  stale fallback-account lookup can no longer repopulate cleared state.
- GitHub mutation bursts now batch each affected pull-request row once per
  observer delivery. Attribute observation is limited to `class`, `href`, and
  `id`, while the body-wide subtree boundary remains in place for added rows,
  SPA updates, and fallback layouts.
- Extension-owned reviewer nodes and volatile relative-time elements are
  excluded before fingerprint work, so their updates do not trigger reviewer
  refreshes.

### Quality & Packaging

- In the deterministic 25-row request-shape fixture, peak reviewer-summary
  concurrency drops from 25 to 4 while the total remains 25 requests and the
  first result remains ready after the first modeled 100 ms wave. This timing
  model measures request shape; it is not a production GitHub latency promise.
- In the deterministic mutation-stress fixture, one synchronous burst still
  produces one observer callback, while delivered mutation records drop from
  100 to 60 and row fingerprint calculations drop from 60 to 1. Reviewer API
  requests remain at zero before and after the change.
- Unit, fixture-backed, and packaged-extension coverage exercise scheduler
  ordering, permit return, cancellation races, fallback retry safety, added
  rows, metadata changes, SPA render events, and fallback mount variants.
- The release-prep gate passes 513 coverage tests across 36 files, with 91.86%
  statements, 87.56% branches, 96.47% functions, and 91.86% lines, plus 17
  deterministic packaged-extension E2E tests.
- Release packaging continues to require the GitHub App configuration
  preflight, the complete release verification suite, and checked Chrome zip
  validation before upload.

### Authentication & Security

- Public repositories still use the no-token path first when no covering
  account exists. Eligible authenticated fallback attempts use the same queue
  as a second, sequential attempt for the row.
- No extension permission, GitHub App scope, authentication flow,
  storage-schema, host-permission, or reviewer-state semantic changes.

### Scope Notes

- This release changes request scheduling and DOM-observation efficiency; it
  does not add new reviewer states or alter the reviewer chip UI.
- Checks, mergeability, labels, assignees, and general pull-request dashboard
  features remain out of scope.
- Chrome remains the only supported and released browser target.
