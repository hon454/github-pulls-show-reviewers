## v1.14.0

Minor release for **GitHub Pulls Show Reviewers** that keeps reviewer context
visible when GitHub pull-request lists are used in narrow desktop windows or
split-screen layouts.

### Highlights

- Requested users, requested teams, and completed review states now remain
  visible below GitHub's medium-width breakpoint.
- Reviewer chips use an extension-owned responsive metadata container instead
  of inheriting GitHub's `d-none d-md-inline-flex` visibility behavior.
- Standard desktop placement and reviewer chip styling remain unchanged, while
  GitHub metadata that GitHub intentionally hides at narrow widths stays hidden.
- Repeated row processing reuses the existing reviewer mount and removes any
  duplicate roots, including across same-repository SPA rerenders.

### Quality & Packaging

- Packaged-extension Playwright coverage exercises a 640-pixel viewport for
  both the standard GitHub metadata structure and the title-only fallback DOM
  fixture.
- Unit coverage verifies extension-owned placement, GitHub wrapper preservation,
  fallback determinism, duplicate cleanup, accessibility labels, and
  focus-visible styling.
- The release-prep gate passes 487 coverage tests across 35 files, with 91.29%
  statements, 87.90% branches, 96.66% functions, and 91.29% lines, plus 16
  deterministic packaged-extension E2E tests.
- Release packaging continues to require the GitHub App configuration preflight,
  the complete release verification suite, and checked Chrome zip validation
  before upload.

### Authentication & Security

- No extension permission, GitHub App scope, authentication, storage-schema,
  or host-permission changes.
- Public repositories still work without signing in when GitHub's
  unauthenticated API allows it; private repositories continue to use the
  maintainer-owned GitHub App with `Pull requests: Read` access only.

### Scope Notes

- This is a reviewer-visibility fix for narrow desktop and split-window layouts,
  not general mobile-browser support.
- Checks, mergeability, labels, assignees, and general pull-request dashboard
  features remain out of scope.
- Chrome remains the only supported and released browser target.
