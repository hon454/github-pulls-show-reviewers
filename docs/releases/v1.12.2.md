## v1.12.2

Patch release for **GitHub Pulls Show Reviewers** focused on access-banner
sign-in recovery from GitHub pull request lists. This release keeps the product
scope unchanged: requested reviewers, requested teams, and completed review
state remain the only pull-list metadata surfaced by the extension.

### Highlights

- Routes access-banner **Sign in** clicks through the extension background
  service worker instead of relying on direct `chrome-extension://` page
  navigation from GitHub.
- Keeps the visible banner copy and fallback link target unchanged while
  avoiding Chrome's blocked-page behavior for auth-expired, sign-in-required,
  and unauthenticated rate-limit banners.

### Authentication

- No permission, token-scope, storage-schema, or host-permission changes.
- Public repositories still work without signing in when GitHub's
  unauthenticated REST API allows it.
- Private repositories continue to use the maintainer-owned GitHub App account
  flow with `Pull requests: Read` access only.
- The extension-internal `openOptionsPage` runtime message is payload-free and
  strict, so unexpected fields are rejected before the background opener runs.

### Quality & Packaging

- Added regression coverage for Sign in click interception, background
  options-page opening, foreign-extension message rejection, opener failure
  responses, and strict runtime-message validation.
- Release packaging behavior is unchanged: GitHub Actions still runs the
  release preflight, `pnpm verify:release`, and checked Chrome zip creation
  before attaching the package to the GitHub Release.

### Scope Notes

- Reviewer visibility on GitHub pull request list pages remains the only
  product goal.
- Checks, mergeability, labels, assignees, and general PR dashboard features
  remain out of scope.
