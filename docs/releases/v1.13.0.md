## v1.13.0

Minor release for **GitHub Pulls Show Reviewers** focused on clearer reviewer
fetch failures, safer GitHub API pagination, and stronger regression detection.
This release also splits the largest reviewer and API modules into focused
boundaries while preserving existing behavior and the extension's narrow
reviewer-visibility scope.

### Highlights

- Unexpected network, schema, and unknown reviewer-fetch failures now surface
  as one accessible page-level unavailable state instead of looking like a
  successful response with no reviewers.
- Stale reviewer chips remain visible when background revalidation fails, while
  successful empty reviewer results remain visually empty.
- Review and issue-event pagination now validates the exact HTTPS GitHub API
  origin and expected endpoint path before request headers can be reused.

### Authentication & Security

- Pagination stops safely for malformed, cross-origin, non-HTTPS, wrong-path,
  non-default-port, credential-bearing, or fragment-bearing next links. Valid
  same-endpoint GitHub pagination and existing request budgets are preserved.
- The scheduled live GitHub canary verifies that a successful public API request
  occurred before checking that no authorization header was sent. Diagnostics
  record authorization presence rather than header values and retain only
  sanitized endpoint, status, and rate-limit evidence.
- The canary checkout does not persist Git credentials and the workflow has
  read-only repository permissions.
- No extension permission, GitHub App token-scope, storage-schema, or host
  permission changes. Public repositories still work without signing in when
  GitHub's unauthenticated API allows it; private repositories continue to use
  the maintainer-owned GitHub App with `Pull requests: Read` access only.

### Quality & Packaging

- The release coverage gate now measures the content script, background worker,
  and options-page TypeScript entrypoints as well as `src/`, with generated WXT
  output excluded.
- A daily and manually dispatchable, read-only canary exercises a real public
  GitHub pull-request list. It remains separate from blocking, fixture-backed PR
  E2E checks and retains screenshots, traces, sanitized diagnostics, and DOM
  evidence for failures.
- GitHub API transport, parsing, reviewer aggregation, diagnostics, page
  metadata, request deduplication, fallback-account handling, row lifecycle,
  and runtime messaging now live behind focused typed boundaries. Existing
  facade imports, cache freshness, retry behavior, stale rendering, pagination
  validation, and route teardown semantics remain compatible.
- Release packaging still runs the GitHub App configuration preflight,
  `pnpm verify:release`, and checked Chrome zip validation before any upload.
- The final release-prep gate passed 450 coverage tests across 35 files and 14
  deterministic packaged-extension E2E tests. The checked Chrome package
  reports manifest version `1.13.0` and contains the expected production GitHub
  App configuration.

### Scope Notes

- Reviewer visibility on GitHub pull request list pages remains the only product
  goal.
- Checks, mergeability, labels, assignees, and general pull-request dashboard
  features remain out of scope.
- Store listing copy, screenshots, privacy disclosures, extension permissions,
  and storage behavior are unchanged in this release.
