## v1.18.1

Repository PR-list compatibility and development-tool dependency maintenance
for **GitHub Pulls Show Reviewers**.

### GitHub PR-list compatibility

- Render reviewer information in both classic and Dashboard Preview repository
  pull request lists, selecting the adapter from the current DOM.
- Support Preview row and title fallbacks, inline reviewer placement, and
  replacement or empty-list transitions without changing GitHub's Preview setting.
- Ignore changing timestamps and Preview inline check status in row cache
  fingerprints so unrelated updates do not trigger duplicate reviewer requests.

### Dependency maintenance

- Upgrade WXT to 0.21.4 with an explicit Vite 8.2.2 peer. Exclude the optional
  Firefox runner (`web-ext`) to remove the vulnerable `firefox-profile` →
  `adm-zip` dependency path tracked in
  [#195](https://github.com/hon454/github-pulls-show-reviewers/issues/195).
- The release-preparation full and production dependency audits report zero
  findings. This removes the vulnerable path; it does not claim an upstream
  patched `adm-zip` release. Vitest and V8 coverage remain at 4.1.11, already
  included in v1.18.0.
- Development requires Node.js 22.12+ or a newer supported LTS. `pnpm dev`
  starts WXT without opening a browser; load `.output/chrome-mv3-dev` manually.

### Compatibility and verification scope

- Existing accounts, display preferences, review-state semantics, permissions,
  host access, OAuth scope, and storage boundaries remain unchanged.
- Public repositories retain no-token access subject to GitHub API limits;
  private repositories continue to use the maintainer-owned GitHub App with
  `Pull requests: Read`.
- Regression coverage includes classic and Preview fixtures, row replacement,
  empty lists, and packaged extension behavior. Live GitHub canary behavior and
  the full development HMR workflow are not claimed as release-verified.
- A Vite diagnostic about importing public-directory JSON appeared during the
  development smoke check; service worker and options-page checks still passed.
