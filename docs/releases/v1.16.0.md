## v1.16.0

Five-language localization release for **GitHub Pulls Show Reviewers**.

### Highlights

- Extension-owned UI now supports English, Korean, Japanese, Simplified Chinese,
  and Traditional Chinese: options, accounts, device sign-in, repository
  diagnostics, reviewer labels and access guidance.
- Language defaults to **Auto**, following Chrome's UI language with English
  fallback for unsupported languages. A manual selection is saved locally and
  survives browser restart. Existing accounts and display preferences are retained.
- Language changes rerender retained UI state without restarting reviewer-data
  requests, diagnostics or sign-in. Ordinary time-driven authentication polling
  and avatar requests remain separate from this render-only guarantee.
- Chrome selects packaged name, description and toolbar metadata independently.
  The manual UI selector does not change Chrome metadata or store listing language.
  Five reviewed store descriptions and matching screenshot sets are prepared;
  their dashboard registration is a separate release step.

### Authentication & Reviewer Semantics

- Public repositories continue to support no-token access, subject to GitHub's
  unauthenticated API limits. Private access still uses the maintainer-owned
  GitHub App's OAuth Device Flow and only `Pull requests: Read`. Both the account
  and App installation need repository access. Multiple accounts remain supported.
- Credentials remain in local extension storage; authenticated API requests stay
  in the background worker. No new permissions, host scope or remote translation
  service is introduced.
- Requested reviewers and teams remain visible. Completed state prefers each
  reviewer's latest non-`COMMENTED` review, falling back to the latest `COMMENTED`
  review only when no non-comment review exists. Completed states are `APPROVED`,
  `CHANGES_REQUESTED`, `COMMENTED` and `DISMISSED`; unsubmitted `PENDING` is excluded.
- A later `review_requested` event is still required for the refresh badge after
  approval, changes requested or dismissal. Teams never imply aggregate approval.
  The open-PR preference filters reviewer-link destinations, not which rows render.

### Quality & Packaging

- Five complete bundled catalogs have strict key, placeholder, Chrome message
  format and emitted-package parity checks. English is the complete fallback
  contract; shipped translations are not deliberately left incomplete.
- Fixture-backed checks cover five-language narrow/desktop screens, cross-tab
  state, request counts, native Chrome metadata and browser-process persistence.
  A reproducible isolated-profile upgrade probe runs the published v1.15.0 ZIP
  before replacing the same extension path with the checked v1.16.0 package.
- Production packaging retains the GitHub App preflight, full release verification
  and checked ZIP/config inspection. Store captures use synthetic **TESTING**
  configuration and are not production-package or private-access evidence.
- The localized release uses receipt-bound upload-only staging, separately saved
  and reopened listings, then authorized submission for normal review and automatic
  publication after approval. Local readiness does not mean uploaded or published.

### Scope Notes

- GitHub pages, PR titles, usernames, team names and external authorization pages
  are not translated. Landing, privacy and developer documentation remain English.
- Controlled Chromium fixture checks do not establish live private-repository
  access, every OS/browser-language combination, screen-reader pronunciation,
  saved dashboard listings or publication. See the release-readiness handoff for
  the exact executed evidence and remaining release authority.
- Chrome remains the released target. Checks, mergeability, assignees, labels and
  general PR-dashboard features remain out of scope.
