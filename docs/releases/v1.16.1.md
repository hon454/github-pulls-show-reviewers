## v1.16.1

Reliability and accessibility fixes for **GitHub Pulls Show Reviewers**.

### Fixes

- Coordinate concurrent authentication failures and recovery so an older request
  cannot invalidate a newly recovered account or overwrite newer credentials.
- Keep reviewer requests safe across navigation, display changes and replaced
  GitHub rows. Restore missing reviewer mounts from retained results without
  duplicating requests or leaving completed rows stuck on loading.
- Refresh access guidance after reviewer recovery and restore its placement when
  GitHub replaces the toolbar. Language changes preserve the current outcome.
- Prevent delayed responses from canceled or replaced GitHub sign-in attempts
  from starting an account save or closing a newer sign-in panel.
- Make account removal a native keyboard-accessible button, including invalidated
  accounts and removal of the last saved account.
- Update vulnerable development dependencies while retaining checked release
  packaging and the existing production dependency scope.

### Compatibility

- English, Korean, Japanese, Simplified Chinese and Traditional Chinese remain
  supported. Language changes rerender retained state without restarting data
  requests.
- Public repositories retain no-token access, subject to GitHub API limits.
  Private repositories continue to use the maintainer-owned GitHub App and
  `Pull requests: Read`; multiple accounts remain supported.
- Reviewer-state semantics, stored account records, permissions and supported
  GitHub host scope are unchanged. No migration is required.
