## v1.12.3

Maintenance release for **GitHub Pulls Show Reviewers** focused on release
operations. This release keeps extension runtime behavior and product scope
unchanged: requested reviewers, requested teams, and completed review state
remain the only pull-list metadata surfaced by the extension.

### Highlights

- Added automated Chrome Web Store API v2 submission to the tag-triggered
  GitHub Actions release workflow.
- New versions are submitted for review after all release checks pass and are
  published automatically after Chrome Web Store approval.
- Added safe manual workflow modes for skipping store submission, validating
  credentials without uploading, or intentionally publishing a checked build.

### Authentication

- Chrome Web Store automation uses the publisher-linked service account already
  configured for this repository.
- No extension permission, GitHub token-scope, storage-schema, or
  host-permission changes.
- Public and private repository authentication behavior remains unchanged.

### Quality & Packaging

- Verified the Chrome Web Store service-account credential with a non-uploading
  GitHub Actions dry run before this release.
- Release packaging still runs the GitHub App configuration preflight,
  `pnpm verify:release`, and checked Chrome zip creation before store
  submission.
- Added release-operation guidance for credential rotation, failure recovery,
  and secret handling.

### Scope Notes

- There are no user-facing extension behavior changes in this release.
- Reviewer visibility on GitHub pull request list pages remains the only
  product goal.
- Store listing copy, screenshots, privacy disclosures, and other dashboard
  metadata remain manually managed when they change.
