## v1.18.2

Release operations and saved-listing verification improvements for
**GitHub Pulls Show Reviewers**.

### Release status and listing reuse

- Add a read-only `status` workflow with sanitized JSON and Actions Summary for
  published and submitted versions, verified package receipts, remaining
  listing work and actionable blockers.
- Keep status observations in a separate queue so they cannot replace a pending
  release. Incomplete concurrent receipt observations require another read.
- Reuse reviewed saved-listing evidence when all five submitted descriptions and
  their ordered screenshots are unchanged. Compare actual description text,
  preserving whitespace, while retaining whole-file hashes for source provenance.
  Contributor notes outside the description no longer trigger listing updates.
- Preserve verified package reuse alongside outstanding listing work. Wait for
  pending review without cancellation; perform scoped listing edits after
  publication without reuploading an existing package.

### Compatibility and verification scope

- Reviewer display, review-state semantics, accounts, preferences, permissions,
  host access, OAuth scope and storage boundaries remain unchanged.
- Manual `skip` remains the default. Credential-only `dry-run` and read-only
  `status` do not authorize publication. Release writes retain fresh API and
  receipt checks, production preflight, release verification and checked packaging.
- Regression coverage includes queue isolation, incomplete receipt provenance,
  package reuse with changed or missing listing evidence, description-marker
  validation and contributor-only edits in all five locales.
- The status API does not prove saved dashboard content or remote draft ZIP
  identity. Actual saved/reopened evidence remains necessary for listing reuse.
