## v1.18.8

Authentication and background resilience for **GitHub Pulls Show Reviewers**.

### Sign-in

- Keep a sign-in through a transient GitHub or network failure after you
  approve the device code. The extension retries `/user` and the installation
  list a bounded number of times. If only the installations fail, the account
  connects and loads them shortly after.
- End a stalled sign-in with the existing network error after about 15 seconds,
  instead of leaving the options panel waiting until you cancel or the code
  expires.
- Let accounts with more than 1,000 GitHub App installations sign in and
  refresh, using the installations loaded before the page limit.

### Token refresh

- Keep rotated tokens when saving them fails once after GitHub has already
  rotated them. The save is retried, so a transient local storage failure no
  longer forces you to sign in again.
- Stop OAuth, token refresh, `/user` and installation requests after 15
  seconds. A hung refresh no longer holds every later recovery for that
  account; the next attempt starts a new exchange.

### Connected accounts

- Identify connected accounts by the numeric GitHub user ID instead of the
  login. After a GitHub username change, signing in again updates the existing
  account instead of adding a second one. Accounts saved by earlier versions
  keep working without signing in again and gain the ID from a later GitHub
  response.
- Keep an account record that this version cannot read, for example after
  downgrading, instead of deleting it. Its credentials are not used, and the
  account shows "Sign in again" until you sign in again, remove it, or install
  a version that can read it.

### Background and privacy

- Start repository discovery promptly in a new GitHub tab even when other
  GitHub tabs are slow to respond, and recover from a malformed session record
  instead of failing every later discovery.
- Send the content script on GitHub pages only an opaque account ID, credential
  revision and validity flag, never the account's login, avatar or the accounts
  where the GitHub App is installed. The options page still shows the full
  account summary.
- Remove unused internal paths that could have written credentials without the
  usual checks. Behavior is unchanged.

### Tests and tooling

- Update Vitest to 5.0.3, Vite to 8.3.2, jsdom to 30 and Playwright to 1.63.
  Unit tests now need Node.js 22.22.2+ (22.x), 24.15+ or 26+; Node 23 and 25
  are not supported.

### Compatibility

- **Chrome 140 or later is required.** The manifest now declares
  `minimum_chrome_version: "140"`, because the storage access restriction the
  extension applies before serving any request needs Chrome 140. Chrome 139 and
  older could install earlier versions, but every request failed there; they
  can no longer install the extension, and existing installs there stop
  receiving updates.
- Permissions, host access, GitHub App scope and all five interface languages
  are unchanged. Stored account profiles gain an optional numeric GitHub user
  ID; earlier versions ignore it. The privacy policy describes the stored ID,
  the kept unreadable records and what the content script receives.
- All five store descriptions and all 15 screenshots are unchanged; reuse the
  verified saved-listing baseline.
