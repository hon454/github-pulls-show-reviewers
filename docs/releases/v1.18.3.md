## v1.18.3

Reviewer freshness and account recovery fixes for **GitHub Pulls Show Reviewers**.

### Reviewer freshness

- Preserve meaningful pull-request row changes while reviewer requests are
  loading, revalidating stale data, or waiting for a summary slot. Changes during
  one request coalesce into one eligible follow-up using current page metadata.
- Prevent older page-metadata batches from supplying stale reviewer information
  to that follow-up. Preserve the four-slot FIFO scheduler, cancellation,
  failure admission, and render-only display/language changes.

### Account recovery

- Complete interrupted local account deletion on background initialization,
  including orphaned records left by earlier versions. Keep registered accounts
  and unrelated preferences intact during cleanup and reconnection.
- Isolate installation refreshes by credential generation. Older work cannot
  replace a newer refresh result, report a skipped write as success, or invalidate
  newer credentials after another refresh takes ownership.
- Preserve normal authenticated retries and account invalidation when concurrent
  requests join before or after a conditional storage decision.

### Compatibility and verification

- Permissions, GitHub App scope, reviewer-state semantics, stored record schemas,
  and the five supported interface languages are unchanged.
- Deterministic reviewer/metadata and real account-owner regressions cover the
  fixes, alongside normal unit/coverage and packaged extension E2E checks.
  Live GitHub/Chrome race reproduction was not performed.
- All five Chrome Web Store descriptions and all 15 screenshots are unchanged.
  The release capture matches the existing images; saved listings can be reused.
