## v1.17.0

More reliable multi-account repository access and background-owned authentication
for **GitHub Pulls Show Reviewers**.

### Improvements

- When an authenticated repository request returns 403/404 without a rate-limit
  signal, try other eligible connected accounts for the same owner in a bounded
  sequence. Accounts with known installation coverage come first, followed by
  incomplete selected-repository snapshots, preserving saved account order.
- Share account discovery across repository metadata, reviewer rows and matched
  diagnostics. Each candidate is admitted once per page/repository generation;
  successful access and diagnostics retain the identity of the account used.
- Keep OAuth, authenticated GitHub requests and credential storage in background.
  Content and options use validated capabilities, account summaries and sanitized
  sign-in progress without receiving access tokens, refresh tokens or device-code
  secrets. Chrome restricts content storage; the options boundary is enforced by
  application code because options remains a trusted extension page.

### Reliability

- Stop account discovery on rate limits, unresolved 401, network/schema/server
  errors or cancellation. Authentication recovery stays within the same account;
  an individual pull request's 404 does not reject the entire repository.
- Preserve consumed discovery attempts across worker suspension. Language and
  display changes, row replacement, cache expiry and token rotation do not reset
  the discovery budget or repeat failed candidates.
- Preserve independent cancellation, the four-request FIFO limit, retained
  reviewer chips and page-level access guidance for mixed row outcomes.

### Compatibility

- Existing connected accounts and display preferences are preserved on upgrade.
- Public repositories retain no-token access, subject to GitHub API limits.
  Private repositories use the same maintainer-owned GitHub App with
  `Pull requests: Read`; connecting an account does not grant repository access.
- English, Korean, Japanese, Simplified Chinese and Traditional Chinese remain
  supported. Reviewer-state semantics and extension permissions are unchanged.
