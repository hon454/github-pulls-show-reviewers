## v1.12.0

Minor release for **GitHub Pulls Show Reviewers** focused on clearer
private-repository access diagnostics and safer GitHub App account handling.
This release keeps the product scope unchanged: requested reviewers, requested
teams, and completed review state remain the only pull-list metadata surfaced
by the extension.

### Highlights

- Added structured repository diagnostics to the options page so users can see
  which signed-in GitHub App accounts can read the current repository.
- Improved the diagnostics model with explicit success, denied, missing, and
  unknown states instead of relying on raw request failures.
- Detects truncated GitHub App installation snapshots and refreshes them before
  deciding that an account cannot access a repository.

### Authentication

- No permission, token-scope, storage-schema, or host-permission changes.
- Public repositories still work without signing in when GitHub's
  unauthenticated REST API allows it.
- Private repositories continue to use the maintainer-owned GitHub App account
  flow with `Pull requests: Read` access only.
- Stored account snapshots now track whether the installation repository list
  was complete, avoiding false negative access checks when GitHub returns a
  paginated installation response.

### Quality & Packaging

- Added regression coverage for truncated installation snapshots, account
  refresh behavior, repository diagnostics view models, and repository access
  API classification.
- Updated manual testing guidance for repository diagnostics in the options
  page.
- Release packaging behavior is unchanged: GitHub Actions still runs the
  release preflight, `pnpm verify:release`, and checked Chrome zip creation
  before attaching the package to the GitHub Release.

### Scope Notes

- Reviewer visibility on GitHub pull request list pages remains the only
  product goal.
- Checks, mergeability, labels, assignees, and general PR dashboard features
  remain out of scope.
